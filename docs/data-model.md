# Sumi 数据模型

模型只服务个人日常收支。保留来源、原币交易、复式分录和操作历史，为基础统计保存必要结构，不引入企业往来和资产成本模型。

## 用户与账本

| 实体 | 关键字段 |
| --- | --- |
| User | id、认证 issuer 与 subject、展示名、状态 |
| Ledger | id、owner_user_id、reporting_currency、timezone、revision |
| AuthorizationGrant | user_id、client_id、scope、授权账本范围、状态 |

第一版每个用户拥有一个独立账本。所有业务实体包含 ledger_id，权限取当前用户所有权与 OAuth scope 的交集。组合外键和 RLS 阻止跨账本读写；不设计成员和角色表。

## 账户和统计分类

| 实体 | 关键字段 |
| --- | --- |
| Account | id、name、type、currency、role、parent_id、external_identifiers、status、version |
| Category | id、name、income_or_expense、可选 parent_id、status、version |
| Tag | id、name、status |
| Preferences | 展示币种、分类规则、商户别名、版本 |

Account 使用 asset、liability、income、expense、equity 五类。银行、钱包、现金和信用卡是实际账户；收入、费用、期初权益、待查、在途和货币交换科目由系统按币种生成。

分类与标签保存稳定 ID。一个消费可以按金额拆成多个分类，每项可带简单标签。商户保留原始名称和归一化名称，不建设独立交易主体或复杂维度平台。

Account 有历史分录后不能直接修改类型或币种；停用代替删除。Category 更名或统计重分类保留历史，纯分类变化不冲销未改变的金额。

## 来源与观测

| 实体 | 关键字段 |
| --- | --- |
| Source | id、provider、source_scope、external_id、origin_uri |
| SourceVersion | source_id、正文、服务器哈希、capture_kind、保存时间 |
| Observation | 稳定 id、source_id、type、current_version、version、review_note、可选 ignored_reason |
| ObservationVersion | observation_id、version、source_version_id、record_locator、提取载荷、引用位置、提取者、修改理由 |
| ImportBatch | id、名称、来源范围、提交状态、实际提取条数与按币种收付合计 |

原文和提取结果分别保存；原文不可覆盖，提取更正有版本。保存级别区分 original、excerpt、ai_normalized、user_statement。外部链接不等于附件内容已归档。

Observation.version 用于所有更新的并发检查，current_version 只指向提取载荷的版本；更新处理备注或忽略理由不改变 current_version。

观测包括 movement、order、authorization、balance、statement、fx_quote。预授权和未付款订单只保留资料，不算已发生支出；第一版不建设完整预授权处理引擎。

来源身份按账本及提供方作用域唯一；材料位置唯一键为来源版本、record_locator 和类型，映射到稳定的 Observation.id。重提取或原材料换版时，确认是同一行就沿用该 ID，不能新建一份资金观测。换版后无法确认行对应关系时标记来源冲突，解决前这些行不能支持新增交易或作为已匹配流水。批次只是分组，不影响交易去重，也不是跨调用数据库事务。

statement 观测保存账户、币种、账单期间 `[period_start, period_end)`、来源版本、已取得范围、完整性依据及期初期末余额。账单提供时才保存 `expected_count`、`expected_debit_total`、`expected_credit_total`，各值附原文定位；缺失与零不同，三项均为可选。有一项就校验一项，不要求凑齐。ImportBatch 的实际提取数量和合计由服务端计算，不能反填为应有控制值；净变动不能替代分别统计的收款和付款总额。

## 交易与分类拆分

Transaction 有稳定 ID、current_version 和 version。TransactionVersion 保存 kind、state、occurred_on、可选 occurred_at、各实际账户入账日期、money、可选 original_money、merchant、description、allocations、fees、tags、外部交易标识、可选 review_note 和修改原因。

- kind 为 expense、income、transfer、refund、opening、unresolved_movement。不同币种转账也是 transfer。
- money 是实际记账金额及币种；跨币种转账保存 from_money 和 to_money；original_money 仅作商品原价背景。
- allocations 每项有稳定 allocation_id，保存分类与金额，合计等于对应收支组成项。转账的费用有独立分类分配，不能与本金混加。缺少明细时不补造商品信息。
- 退款关系保存原交易、原 allocation_id、逐项已退原币本金和实际到账。累计退款同时受原消费总额和各分配项金额限制，分类读取原分配项的当前分类，不另猜比例。原消费重分类保留 allocation_id；删除被退款引用的分配项、将其金额降到累计退款以下，或作废已有有效退款的原消费时，必须在同次 apply 中合法修正相关退款，否则拒绝。
- 日期不足时保留实际精度，不补造时刻；入账日期为推断值时不能宣称跨期对账已确认。

状态为 posted、voided，待处理提取数据保留在 Observation。未知分类可用未分类；已知消费但付款账户未知时用专用未知账户，并标记待补。银行扣款性质未知时进入待查科目，不直接计作消费。

已知是转账但仅有转出依据时，使用 unresolved_movement 并标记 `purpose=transfer_in_transit`，对方为同币种在途科目；不得补造收款金额。到账后以同一交易 ID revise 为 transfer，保留两侧真实入账日期。普通未知用途资金仍进入待查科目，具体分录见[多币种记账](currency-accounting.md#换汇与跨币种还款)。

posted 与质量标记分开。证据缺失、待复核、未知账户、待查、在途未完成等由当前数据导出，交易查询和报表均返回，不另建审批状态机。待复核的已入账收支仍计入当前统计，同时返回受影响金额，不能因证据变化静默隐藏旧账。

## 不可变复式分录

JournalEntry 保存 id、transaction_version_id、effective_on、recorded_revision、operation_id、reverses_entry_id。JournalLine 保存 entry_id、account_id、currency、amount_minor。

金额为最小单位整数字符串，数据库使用限制为 38 位整数的 NUMERIC domain，主动拒绝小数而非由 NUMERIC(38,0) 隐式舍入，借正贷负。每张凭证至少两条非零分录，每个币种的金额合计严格为零。跨币种用各币种交换科目连接，详见[多币种记账](currency-accounting.md)。

Rust 领域金额使用包装 i128 的受限类型，构造时检查币种精度和范围，加减与汇总使用 checked 运算。SQLx 通过 BigDecimal 与 NUMERIC 无损转换，进入领域前检查确为整数；序列化始终输出金额字符串，不经 f32 或 f64。溢出和非法小数返回错误，不截断或绕回。

正式凭证不可更新或删除，运行角色权限与提交平衡检查共同约束。财务修改追加旧凭证的完整冲销和更正凭证；余额累计所有正式分录，包括冲销。纯分类、标签或说明修改只生成资料版本与操作记录。

“当前有效凭证”仅指尚未被冲销的原始或更正业务凭证，不包含冲销凭证本身。一次更正只冲销这组凭证，不能再次冲销旧版本或把原冲销凭证作为更正对象。

### 日期与纠错

- 收支统计按 occurred_on，即消费、收入或真实退款的发生日；账户余额与对账按各账户的实际入账日。
- JournalEntry.effective_on 对应资金入账日。转账两侧日期不同时，经在途科目生成各日独立平衡的凭证。入账日暂缺可显式使用推断值，但不能据此确认跨期对账。
- 修改金额、实际账户或入账日时，完整冲销当前有效凭证；冲销沿用各旧凭证的 effective_on，更正凭证使用更正后的入账日。不能把发现错误的日期当作冲销生效日。
- 只改 occurred_on 且不影响资金分录时属于资料更正，重新归属收支期间。真实退款使用退款发生日和实际到账日，不回填为原消费日。
- 操作时间和 recorded_revision 表示何时获知并记录更正，不替代业务日期。第一版报表展示当前已知事实；历史版本用于审计和重算，不增加任意历史版本报表接口。无法确定归属期间的日期明确返回未归期项目。

期初按实际账户原币记录，对方为对应币种期初权益，使用跟踪起点前一日收盘。零期初保存已确认基准，未知期初单独标记；不需要外币历史成本。

## 去重和证据

TransactionIdentifier 的强唯一键包含账本、标识命名空间、金融账户作用域、事件类型和外部 ID。订单号、结算号和退款号分开处理，停用或作废后仍保留身份记录。

EvidenceLink 关联观测版本、交易、实际金融账户分录、作用、原币分配金额、有效版本区间和操作理由。同一交易可以有多份来源，资金证据必须与对应账户、币种和收付方向相符。金额占用按稳定 Observation.id 计算，不能按版本各算一份；一份观测拆给多笔交易时，合计不能超过其当前金额。不同独立来源分别校验，不把多份证据的金额相加当成交易金额。已关闭的历史关联和冲销不再次占用证据。

### 观测换版与证据复核

1. 新版观测保存成功时，在同一事务中将旧版的当前证据关联标记为待复核，保留其占用和历史，并更新受影响交易的质量标记。原交易和正式分录保持不变；旧版关联不能再证明当前证据完整。
2. 新金额小于已占用金额，或币种、账户、方向改变时，允许保存真实更正并呈现冲突。除下一步的原子复核外，复核完成前禁止该观测产生新分配，不能以换版绕过原占用。
3. AI 通过 apply 原子更正交易并重绑新版证据，或关闭不成立的关联。服务端在最终状态重新检查占用、账户、币种和方向；旧占用在关闭时释放，新关联只计一次。若决定保留交易但撤去证据，交易必须显示证据缺失。
4. 只修改观测的处理备注或忽略理由，更新 Observation.version 并保留操作历史，不改变提取版本、证据关联或金额占用。实际提取载荷或来源引用改变才走上述复核。无法确定时保留待复核，不能自动补平或自动改动金额。

所有基础业务变更均递增账本版本，第一版保守地使旧对账结果过期；不实现精细依赖失效系统。

仅同日同商户同金额时返回重复候选，AI 可判断为同笔、独立或待定，不能绕过强标识和覆盖约束。强标识相同而金额或币种不同必须报告冲突。

### 处理备注与修改历史

第一版只保留现有实体上的简单备注，不建独立决策实体或依赖失效系统。review_note 是给下次整理阅读的简短说明，可引用相关观测或交易 ID；它不代表服务端确认，也不绕过强标识、金额、证据和退款约束。

- 不需入账的非资金资料可填写 ignored_reason，从待处理列表移出；真实资金观测不能通过忽略消除覆盖要求，重复材料应关联到已有交易。实际提取载荷换版时清除当前忽略标记，旧标记仍可从操作历史追溯。
- 两笔真实消费被判断为独立时，可通过普通 revise 保存备注，不新增分录。重复候选仍可附带返回，AI 阅读已有解释和最新资料，不要求服务端维护候选抑制、结论到期或规则依赖。
- 更正已有交易需 expected_version 和修改理由，可附新证据。AI 自动分类默认只补未分类项，显式更正可以修改已有分类；第一版不实现字段保护、证据优先级或专用纠正授权机制。备注和理由用于审计，服务端校验结构与账务合法性，不认证解释本身的真实性。

## 对账结果与导入完整性

每次按账户、币种、期间和指定来源版本计算两个独立结果，共用 ledger_revision 和范围信息；不再用一个状态同时承诺匹配与完整。范围或日期不足时明确返回不能执行的检查。账本版本变化后两个旧结果均标记过期，按需重算。

### 对账结果 reconciliation

检查已导入的资金行与所选账户期间的当前有效资金组成项是否双向足额匹配，以及账本期初加原币净变动是否等于期末并与账单余额一致。匹配必须核对账户、币种、方向和入账日期，待复核证据不能用于匹配。已冲销凭证不作为额外真实流水，余额仍累计全部正式分录。

| status | 含义 |
| --- | --- |
| reconciled | 余额相符，已取得流水与账本在指定范围内双向足额匹配，无匹配冲突或待复核证据 |
| balance_matched | 余额相符，但仍有未匹配项、待复核证据，或仅取得余额而未进行逐笔检查 |
| mismatch | 账本与账单存在余额差额，返回具体差额和未匹配项 |
| incomplete | 缺少可比较余额、范围或必要日期等，无法完成对账判断 |

同时返回逐项检查及未匹配项。只有余额资料时不能以空集合匹配宣称 reconciled；有来源明确支持零流水的期间可以核对空集合。账单条数或收付总额缺失不阻塞上述检查，也不单独降低对账结果。

### 导入完整性 import_completeness

检查指定期间的材料是否取得完整、材料中的资金行是否提取完整；结果必须附依据和限制。

| status | 含义 |
| --- | --- |
| complete | 有覆盖完整期间、完整资金记录集合的依据，已取得并提取完该范围，所有可用控制检查通过 |
| incomplete | 已知只取得部分材料、分批提取未完成，或任一可用控制值不符等，存在已知缺口或冲突 |
| unknown | 没有已知缺口，但依据不足以确认完整；控制值缺失本身不等于已知漏导 |

完整性依据可以是可核对的完整结构化导出及记录范围、分页与逐行定位，或账单控制数据与完整来源范围的组合。仅取得全文、AI 声明“完成”、提取结果自身的合计或余额相等，都不足以单独证明所有资金行已提取。第一版只使用已保存且能核对的依据，不能核对就返回 unknown，不增加通用文档验证引擎。complete 表示这些依据支持完整性，不独立认证外部材料真伪。

条数、付款总额和收款总额各自返回 matched、mismatch 或 unavailable；有则必须核对，不符使完整性为 incomplete，缺少则说明未检查，不补造值，也不要求三项齐全。缺少全部汇总值时，若仍有可核对的完整记录集合，可以为 complete，否则为 unknown。普通重导保留该来源已有的控制值；修正误提取的值须附来源定位和修改理由、保留版本历史，不能通过漏传字段自动消除已知差异。

reconciled 可以与 unknown 或 incomplete 并存，只能表述为“已取得资料与账本匹配，导入完整性未知/存在缺口”。complete 也可以与未匹配或余额差额并存，说明资料已全但账还需处理。查询和 AI 汇报必须同时呈现两项，不将其中一项推广为整个账本可信或绝无遗漏。

## 汇率与统计

FxRate 保存币种对、方向、日期、精确比例、来源和不可变版本。交易可保留有来源的实际结算展示金额；汇率折算不会改写原币分录。

统计按日期、账户、币种、分类、商户、标签过滤和分组，分别返回收入、原始支出、退款和净支出。第一版定义统一的“当前有效业务视图”，直接通过数据库查询实现，不增加分析库或后台流水线：

- 选择每笔未作废交易的 current_version，展开收入、支出、真实退款及独立手续费组成项。分类与标签读取当前分配关系；退款分类沿用原消费当前 allocation_id 的分类。
- 当前收支组成项与该交易尚有效的收入费用分录按原币金额校验一致；纯资料改版沿用已有资金分录。不能沿 JournalEntry.transaction_version_id 直接使用旧分类，也不能只按顶层 kind 过滤而漏掉转账手续费。
- 原始支出是当前有效消费和费用之和；退款只计有效 refund 的原消费已退本金；净支出为两者之差。纠错冲销、被替代业务版本和已作废交易不作为新收支。账户余额仍累计含冲销在内的全部正式分录。
- 消费 100 更正为 80 后，当前原始支出为 80、退款为 0；不将正负分录机械汇总成支出 180、退款 100。发生在以后月份的真实退款属于退款发生月，可使该月净支出为负。
- 返回统计日期口径、当前账本版本和质量标记；受证据待复核、未知字段或缺报价影响的项目及金额单独列明。统一币种展示附汇率口径和未折算项目，不提供企业财报或外币成本分析。

## 操作与恢复

Operation 保存实际用户、客户端、幂等键、请求哈希、实体前后版本及修改摘要、修改理由、凭证引用和结果。观测备注和忽略标记的变化也留在这里。幂等命名空间为账本、客户端和工具，相同键不同请求冲突；成功结果与账务在同一事务中提交并保留。

原幂等键命中时先返回既有结果；同键不同请求仍报冲突。新键请求通过 expected_version 与约束检查后，再检查业务内容是否实际变化。观测载荷及来源引用、交易内容和备注均相同时返回 `changed=false` 和既有实体版本；只增加恢复响应所需的操作结果，不新建业务版本、不追加分录、不递增 Ledger.revision。仅更换请求理由不构成业务变更，来源引用或证据版本改变则需要正常保存和复核。尚未识别为同一交易的新建请求仍按强标识和重复规则处理，不能凭内容相似直接合并。

单次 apply 的多项动作原子成功或失败，修改已有记录必须带 expected_version。证据分配、退款累计和强标识在账本短事务内重新校验，失败不留下半批账。

Ledger.revision 在基础业务数据变化时递增。查询和派生对账结果不自行递增，结果带所用版本。普通分页检测快照过期；交易和操作历史保留未来重算所需信息。

未处理事项由未匹配观测、证据待复核、未知账户、在途未完成、来源冲突、对账差额和已知导入缺口产生，通过上下文及查询返回；完整性未知单独提示依据不足，不自动创建待办。
