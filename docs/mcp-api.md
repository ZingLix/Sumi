# Sumi MCP 接口

接口服务个人日常记账，保留必要能力并减少调用步骤。HTTPS MCP 验证 OAuth 用户，首次使用自动初始化个人账本，不提供成员管理和企业会计接口。

## 公共约定

- `sumi_context_get` 可不带账本 ID，返回当前用户默认账本；其他账本业务调用显式传 ledger_id 并检查所有权。
- 读取使用 sumi:read，修改使用 sumi:write，不接受参数指定操作者。
- 修改请求带 idempotency_key，已有实体修改还带 expected_version。
- 金额为 `{currency, amount_minor}`，最小单位整数字符串。按币种复式平衡，原币准确性不依赖报价。
- 返回结构化 data、ledger_revision、warnings、next_actions；成功修改附 operation_id，业务失败带可修正错误。
- 成功修改返回 changed。原幂等键命中先返回既有结果；新键请求必须先通过 expected_version 校验，相同业务内容返回 changed=false 和既有实体版本，不增加业务版本或账本 revision。新建交易不能仅凭内容相似判为同笔。
- 交易与统计返回质量标记及受影响金额；posted 仅表示已入账。对账响应分别返回 reconciliation 和 import_completeness，共同携带账户、币种、期间、来源版本及 ledger_revision，不合成一个“全部可信”状态。
- 批量导入最多 100 条，批量交易最多 50 个动作，单份正文最多 512 KiB；超限返回分批建议。
- 列表默认 50 项、最多 100 项，使用稳定游标。快照变化返回 CURSOR_STALE，不静默漏项。

结构化结果与业务错误参考[MCP 工具规范](https://modelcontextprotocol.io/specification/2026-07-28/server/tools)，传输和授权见[整体架构](architecture.md)。

## 工具清单

第一版共 16 个工具。

| 工具 | 主要用途 |
| --- | --- |
| `sumi_context_get` | 读取默认账本、账户与分类摘要、偏好、支持币种、未处理事项及处理备注 |
| `sumi_accounts_list` | 查询实际账户、币种、原币余额和期初完整性 |
| `sumi_accounts_upsert` | 创建或更新银行、现金、钱包和信用卡账户，不直接设置余额 |
| `sumi_sources_ingest` | 保存有身份和级别的原文或片段，复用相同版本 |
| `sumi_sources_get` | 按来源版本和定位读取证据 |
| `sumi_observations_ingest` | 批量提交或更正提取观测、更新备注或忽略理由，更新导入批次进度 |
| `sumi_observations_search` | 查询观测、占用与待复核金额、冲突、备注及导入完整性依据 |
| `sumi_fx_rates_query` | 查询个人统计可用的日期报价及来源 |
| `sumi_fx_rates_ingest` | 保存有来源的不可变报价，不改写已知实际结算金额 |
| `sumi_transactions_apply` | 批量新增、更正、作废、关联证据或设置期初，支持资料备注修改和可选预览 |
| `sumi_transactions_search` | 按日期、账户、币种、金额、分类、商户和标签过滤 |
| `sumi_transactions_get` | 读取交易、退款关系、分录、证据、备注与修改历史 |
| `sumi_reconcile` | 按原币核对余额和流水，独立返回导入完整性及可用控制值检查 |
| `sumi_reports_get` | 收支、账户余额、分类汇总、待处理情况及完整导出 |
| `sumi_operations_get` | 查询操作结果、版本和提交历史，恢复丢失响应 |
| `sumi_preferences_update` | 更新分类、标签、商户别名、简单规则和展示偏好 |

分类和标签通过 preferences 的受限结构化数组维护，返回稳定 ID。时区在已有凭证后冻结，展示币种可以更改。系统交换、费用和待查科目由服务端生成，AI 不需要维护整套科目表。

## 来源与观测更正

observations_ingest 更正已有观测时必须传稳定 observation_id、expected_version、来源版本与定位，不能换一个 ID 重提取同一行。材料换版但行身份不明时返回来源冲突，待确认对应关系后继续。

同一工具也可只更新 review_note 或 ignored_reason，保留操作历史，不改变提取版本或证据占用。expected_version 对应 Observation.version；evidence_refs.version 引用提取版本，二者用途不同。忽略真实资金行以绕过匹配时返回字段非法；提取载荷换版后清除原忽略标记。

观测换版与旧证据标记待复核在同一事务完成，返回受影响交易、仍占用金额、是否超额或事实冲突及 next_actions。此调用不改动正式分录。除原子复核操作外，复核前不允许该观测新增分配；AI 后续用 transactions_apply 原子完成交易更正和证据重绑。上下文和检索持续返回未解决影响，调用中断后也能继续。

statement 观测提交账单范围、期初期末和完整性依据；应有条数、付款总额和收款总额均可选，提供时附来源定位。服务端另算实际提取条数与合计；已有控制值逐项校验，缺少就返回 unavailable，不能拿实际值作为应有值。控制不符作为导入质量问题返回，不拒绝保存材料；对账与完整性分别判断，见[数据模型](data-model.md#对账结果与导入完整性)。

## 批量交易动作

`actions[]` 支持 create、revise、void、link_evidence、unlink_evidence、set_opening。备注使用普通 revise 保存，不增加专用决策动作。修改已有记录必须带对应版本，单次调用全有或全无。

新增业务种类为 expense、income、transfer、refund、unresolved_movement。转账支持同币种和跨币种，信用卡还款使用 transfer；手续费是单独的费用组成项。

| 种类 | 关键输入 |
| --- | --- |
| expense | payment_account_id、money、发生日期、入账日期、分类分配、证据 |
| income | receipt_account_id、money、发生日期、入账日期、分类分配、证据 |
| transfer | 付款与收款账户、from_money、to_money、各侧入账日期、可选独立费用 |
| refund | 原消费、实际到账、refund_allocations（原 allocation_id 与原币本金）、收款账户、发生日、到账日及证据 |
| unresolved_movement | 实际账户、确定金额与方向、日期和来源；可选 purpose=transfer_in_transit 表示已知转出在途，其他情况进入待查科目 |

同币种转账的主体金额相同。跨币种保存两侧实际值，各币种通过交换科目平衡。银行总扣款可以同时覆盖转账主体与明确费用，不把手续费算进本金。

每笔收支可分配多个分类，服务端分配稳定 allocation_id 并在结果返回；更正时沿用对应 ID。可选标签、归一化商户和商品原价。分类、标签和说明修改保留资料版本；金额、实际账户和入账日期变更生成冲销与更正分录。退款逐项校验原分配的剩余可退本金，不能以总额未超为由挪用另一分类的额度。

revise 要求修改理由，可附新证据；服务端按最终状态检查退款关系、证据及强标识，不能仅检查本次修改的孤立记录。AI 自动分类默认只补新交易或未分类项，显式更正前读取已有备注及修改历史。第一版不区分纠正授权类型，不设置字段锁或证据优先级。

`preview=true` 时计算校验结果、重复候选及分录，不写任何数据；实际提交使用新幂等键并重新检查。预览是可选步骤，不要求用户确认。

## 消费示例

实现采用 action.transaction.movement 的结构化参数，示例 UUID 需替换为服务返回的实际 ID。完整字段以 MCP 工具 JSON Schema 为准。

```json
{
  "ledger_id": "00000000-0000-0000-0000-000000000001",
  "idempotency_key": "import-payment-123",
  "actions": [{
    "op": "create",
    "transaction": {
      "occurred_on": "2026-09-03",
      "movement": {
        "kind": "expense",
        "payment_account_id": "00000000-0000-0000-0000-000000000002",
        "money": {"currency": "CNY", "amount_minor": "10000"},
        "posted_on": "2026-09-03"
      },
      "allocations": [
        {"category_id": "00000000-0000-0000-0000-000000000003", "amount_minor": "7000"},
        {"category_id": "00000000-0000-0000-0000-000000000004", "amount_minor": "3000"}
      ],
      "evidence_refs": [{"observation_id": "00000000-0000-0000-0000-000000000005", "version": 1}]
    }
  }]
}
```

服务器生成 CNY 费用 +10000、银行 -10000，两项统计分类合计 10000。再次提交原请求返回既有交易；不同来源证明同一消费时关联证据，不新增支出。

## 去重、纠错和待处理

相同材料位置或强结算标识返回既有记录；来源中不同位置可以有不同交易。金额或币种与强标识冲突时保留冲突；同日同商户同金额仅为候选，由 AI 结合资料决定同笔、独立或暂缓。

同一逻辑资金观测跨版本共享占用。财务更正或作废关闭旧证据分配，完整冲销旧金额；更正后的关联须在同次 apply 重绑并校验，否则交易显示证据缺失。纯分类、标签等资料修改保留有效证据，不生成冲销。恢复丢失响应时使用原幂等键或查询操作，不根据超时猜测失败。

review_note 记录重复候选的解释或其他待查说明，可引用相关实体 ID；检索候选时附已有备注，由 AI 结合当前事实处理。备注不会自动抑制候选或解除约束，判断同笔后仍须关联证据或纠正重复入账。忽略理由仅用于不需入账的非资金资料；服务端不维护通用结论、依赖和到期状态。

未分类、未知付款账户、未匹配退款、待查资金变动、在途未完成、证据待复核及已知导入缺口通过上下文与检索返回，附相关实体 ID、当前版本、备注和处理建议。完整性未知只提示依据不足，不自动创建待办；AI 从现有数据恢复工作。

### 单边转账的完整流程

1. 保存转出观测，以 create 建立 `unresolved_movement`、`purpose=transfer_in_transit`，仅传确定的付款账户、金额和入账日，取得交易 ID 与版本。
2. 之后保存到账观测，搜索到同一在途交易，以 revise 将其改为 transfer，传原转出侧、真实到账侧及各侧日期，并附双方证据。
3. 服务端按原日期冲销旧凭证，生成经在途科目连接的完整凭证，原子重绑证据；返回在途已结清。重试或再次整理不新增交易、本金不进入收支。

退款流程同样先保留不确定的收款，再在原消费及具体 allocation_id 明确后 revise 为 refund；不增加独立退款匹配工具。

## 对账与统计

对账输入账户、币种、期间及 statement 观测版本，同时返回两项结果：

- reconciliation：包含期初、变动、期末、差额、逐项检查和双向未匹配明细。余额相符且已取得流水与账本双向足额匹配为 reconciled；余额相符但逐笔未完成为 balance_matched；余额不同为 mismatch；缺少可比较余额、范围或必要日期为 incomplete。仅有余额资料不能当成已核对空流水。
- import_completeness：包含 complete、incomplete 或 unknown，及来源覆盖、完整记录范围依据、缺口和可用控制值的逐项比较。缺控制值返回 unavailable，不因此阻止对账；控制不符或已知范围不全为 incomplete，无法确认是否完整为 unknown。具备可核对完整记录集合时，即使没有汇总控制值也可为 complete。

例如，已取得流水全部匹配、余额相符，但无法确认原账单是否全部提取时，返回 reconciliation.status=reconciled、import_completeness.status=unknown，提示“已取得资料已匹配，导入完整性未知”。完整导入但存在未入账资金行时，可返回 balance_matched 或 mismatch，同时完整性为 complete。不得合并展示为“全部对账成功”。

两个结果共享 ledger_revision；与当前版本不一致就标记过期，按需重算。两者仅适用于指定账户、币种、期间和来源版本，不外推为整个账本已核实。状态的完整判定见[数据模型](data-model.md#对账结果与导入完整性)。

统计支持 income_expense、account_balances、by_category、data_quality、export，按日期、账户、币种、商户和标签过滤。收支与分类读取当前有效业务视图，按发生日返回收入、原始支出、真实退款、净支出及未分类金额；余额按入账日累计全部正式分录。纠错冲销不算退款，转账和还款本金不计收支，独立手续费仍计入支出。data_quality 分开显示对账结果与导入完整性及其范围和时效；未执行的检查不默认成功。第一版固定日期口径并随结果返回，不增加历史版本报表选项。

默认按原币分别汇总，可请求指定展示币种，注明实际结算或日期报价依据及未折算项目。分类折算先按完整组成项用最大余数法分配，再过滤和汇总，规则见[多币种记账](currency-accounting.md#分类折算与舍入)。余额估算与收支可能采用不同折算日期，不作为同一会计口径互相勾稽。

导出包含来源和观测版本、业务版本、正式分录、分类及退款关系、证据占用、处理备注与忽略标记、完整性依据、汇率和操作记录，并基于一致性快照生成，不只导出汇总值。

## 错误

错误包括权限不足、字段非法、币种不支持、幂等键冲突、实体版本冲突、来源冲突、强标识冲突、证据待复核或超额分配、退款总额或分配项超额、游标过期、请求超限和数据库暂时忙。均返回受影响实体和可执行的重读、修正或重试建议。

缺报价仅使折算统计不完整，不阻止原币记账。未知账户或分类可先用明确的系统状态；金额、币种缺失则保留观测。借贷不平衡和真实差额不能用杂项科目自动补平。
