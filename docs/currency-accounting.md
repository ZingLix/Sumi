# Sumi 多币种记账

个人记账优先保证原币金额准确、支出收入不重复、能够按偏好币种查看统计。第一版使用按币种平衡的复式记录，统计折算独立于原始分录。

## 原币记录

每个可记账账户固定一个币种。多币种银行卡或钱包可建立多个币种子账户。收入、费用和系统交换科目也按币种生成，分类通过独立分类 ID 统一表达。

每条分录保存账户、币种、最小单位整数金额。借方为正、贷方为负；每张凭证中每个币种的分录之和都必须为零。不同币种金额不直接相加。

币种精度来自版本化的 [ISO 4217 维护资料](https://www.six-group.com/en/products-services/financial-information/market-reference-data/data-standards.html)。例如 JPY 使用零位、KWD 使用三位，不假定所有币种都是两位小数。

## 常见分录

| 业务 | 分录示例 | 收支影响 |
| --- | --- | --- |
| 银行卡消费 CNY 100 | 费用 +100，银行 -100 | 支出 100 |
| 信用卡消费 CNY 100 | 费用 +100，信用卡负债 -100 | 支出 100 |
| 还信用卡 CNY 100 | 信用卡负债 +100，银行 -100 | 无 |
| 工资到账 CNY 500 | 银行 +500，收入 -500 | 收入 500 |
| 同币种账户转账 CNY 100 | 收款账户 +100，付款账户 -100 | 无 |
| 原消费退款 CNY 30 | 收款账户 +30，原费用 -30 | 净支出减少 30 |

账户余额与银行账单按原币核对，不需要历史买入成本或市场汇率。

## 换汇与跨币种还款

使用 CNY 720 换得 USD 100，追加以下分录：

| 分录 | CNY | USD |
| --- | --- | --- |
| 人民币银行 | -720 | |
| CNY 交换科目 | +720 | |
| 美元银行 | | +100 |
| USD 交换科目 | | -100 |

两个币种分别平衡，真实账户与实际扣款、到账一致。本金不进入收支；另付手续费时单独增加费用。跨币种信用卡还款采用相同方式，收款侧为减少信用卡负债。

交换科目用于连接两种货币的数量变化，按系统角色识别，并从个人消费和收入统计中排除。多币种交换科目的思路参考 [GnuCash Trading Accounts](https://www.gnucash.org/docs/v5/C/gnucash-guide/currency_trading_accts.html)。本项目第一版仅记录交换事实，不生成汇兑收益分析。

只知道转出的一侧时，通过 unresolved_movement 的 `purpose=transfer_in_transit` 先记同币种在途科目，得到到账依据后将同一交易 revise 为 transfer。服务端按普通纠错规则冲销旧凭证并生成完整的两侧凭证，转出日仍使用原日期，不能猜测实际到账额。

例如 1 月 31 日扣 CNY 720、2 月 2 日到账 USD 100，最终有效凭证为：

| 日期 | 分录 |
| --- | --- |
| 1 月 31 日 | CNY 银行 -720、CNY 在途 +720 |
| 2 月 2 日 | CNY 在途 -720、CNY 交换 +720；USD 银行 +100、USD 交换 -100 |

1 月末在途余额为 CNY 720，2 月 2 日结清，各日期各币种都独立平衡。即使起初就已知道两侧金额，只要入账日期不同，也使用这套分录。同日两侧齐全时直接通过交换科目记账。同币种跨日转账在到账日直接记收款账户增加、在途减少，不经过交换科目。

## 消费与退款

以 USD 账户消费 USD 20，记录 USD 费用 +20、USD 账户 -20。第一版不追踪这 20 美元来自哪次换汇，也不计算处置历史成本或已实现汇兑。

境外消费的商品原币与银行卡实际扣款币种可能不同。实际扣款用于记账，商品原价作为可选背景信息保留。例如商品 USD 20、银行卡实际扣 CNY 146，只产生一笔 CNY 146 消费。

同币种退款关联原消费，累计已退本金不得超过原消费。跨币种退款保存实际到账及明确的原消费已退本金，通过交换科目抵减原币费用；资料不足时保留待匹配收款，不直接比较不同币种的金额大小。

退款逐项引用原消费的稳定 allocation_id，并保存各项已退原币本金；同币种时这些本金之和等于实际到账。每项累计退款不得超过该项消费金额，不能只校验整笔上限。只有一个分配项时可直接关联；拆分类消费缺少退款归属时先保留待匹配收款，不默认按比例分摊。原消费分类更正后，当前退款统计随对应分配项使用新分类。

真实退款在退款发生日抵减净支出，银行余额在实际到账日变化。原消费金额更正产生的冲销不算退款；二者的统计规则见[当前有效业务视图](data-model.md#汇率与统计)。

## 统计折算

账本设置 `reporting_currency` 作为默认展示币种，不改变账户原币。

- 收支始终可以按原币分别汇总。
- 消费有明确的展示币种实际结算值时优先展示该事实；否则可使用交易日期的有来源报价折算。
- 余额估算使用所选时点报价，附报价日期与缺失项。
- 缺汇率不阻塞原币入账和原币对账，折算统计明确返回未折算项目。
- 同一报表保存或返回所用报价和数据版本，避免静默混用不同口径。

收支报价日期采用对应组成项的发生日，真实退款使用退款发生日。按不同日期报价折算的消费和退款，展示金额不保证完全相抵；结果说明所用报价，不补造汇兑分录。

折算值是统计信息，不重写原始分录，也不作为持仓成本或正式汇兑损益。第一版不提供跨币种统一资产负债表与汇兑利润表。

汇率方向为 `1 from_currency = rate to_currency`，保存来源、日期和精确十进制或有理比例。换汇交易的实际比例由双方金额推导，不能用市场报价替换已知结算金额。

### 分类折算与舍入

折算使用精确运算。先确定整个收支组成项的目标币种最小单位整数总额 T：有实际结算金额时使用该值，否则将精确折算总额按 half_even 舍入。分类分配使用最大余数法：

1. 对非负金额，以原币各 allocation 金额占比计算精确配额 `q_i = T × amount_i / sum(amount_i)`，每项先向下取整。
2. 将 T 与这些整数之和的差，按小数余数从大到小逐项分配，每次增加一个目标最小单位。余数相同时按稳定 allocation_id 升序决定，不能依赖请求数组顺序。
3. 退款先对正的退款金额执行相同分配，计算净支出时再扣减。消费和退款都不产生负的分类金额；原币合计为零的组成项不参与折算。
4. 先对完整组成项分配，再做分类或标签过滤，最后汇总各组成项已分配的整数金额。不能过滤后重新舍入，也不能先汇总原币再按另一种方式折算报表总额。

例如四个等额分类各精确折算为 0.6 分，总额 2.4 分舍入为 2 分，按稳定 ID 分配为 1、1、0、0 分，合计 2 分。不得让前三项各取 1 分、最后一项承担 -1 分。
